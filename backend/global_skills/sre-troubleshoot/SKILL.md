# SRE 值班排查

## 使用场景

当用户提出生产环境问题需要排查时使用此技能。典型问题：
- 合同签约失败
- 合同状态异常
- 配置问题排查
- 数据不一致问题

## 排查流程

### 第一步：提取关键信息

从用户问题中提取关键参数。**必须根据格式特征准确识别参数类型**：

#### 参数格式识别规则

| 参数 | 格式特征 | 示例 |
|------|---------|------|
| **合同编号** (contract_code) | 以字母 "C" 开头 + 数字 | `C1776759658764987` |
| **订单号** (project_order_id) | 纯数字，通常 18 位 | `826041310000003912` |
| **协议平台合同实例 id** (platform_instance_id) | 纯数字，通常 9 位 | `128266249` |
| **协议平台版式 id** (form_id) | 纯数字，通常 6 位 | `136889` |

#### 识别优先级

1. **看前缀**：以 "C" 开头 → 合同编号 (contract_code)
2. **看长度**：
   - 18 位纯数字 → 订单号 (project_order_id)
   - 9 位纯数字 → 协议平台合同实例 id (platform_instance_id)
   - 6 位纯数字 → 协议平台版式 id (form_id)
3. **看上下文**：用户提到"订单"→ project_order_id，提到"合同"→ contract_code

#### 示例

```
用户：826041310000003912 的合同数据
AI：识别到 826041310000003912 是订单号（18位纯数字），使用 project_order_id 查询。

用户：C1776759658764987 签约失败
AI：识别到 C1776759658764987 是合同编号（以C开头），使用 contract_code 查询。

用户：帮我查一下 128266249 这个合同实例
AI：识别到 128266249 是协议平台合同实例 id（9位纯数字），使用 platform_instance_id 查询。
```

如果信息不完整或无法判断参数类型，主动询问用户补充。

### 第二步：查询合同基本信息

使用 `sre_query` 工具查询合同：

```
sre_query(action="contract", contract_code="C001")
```

或者按订单号查询：

```
sre_query(action="contract", project_order_id="P001")
```

**关注点**：
- 合同状态（status）
- 创建时间
- 最后更新时间
- 是否有异常标记

### 第三步：查询合同节点

使用 `sre_query` 工具查询合同节点：

```
sre_query(action="contract_node", contract_code="C001")
```

**关注点**：
- 流程走到哪一步
- 是否有节点失败
- 节点执行时间是否异常

### 第四步：查询操作日志

使用 `sre_query` 工具查询操作日志：

```
sre_query(action="contract_log", contract_code="C001")
```

**关注点**：
- 最近的操作记录
- 是否有错误操作
- 操作时间线是否连续

### 第五步：查询配置信息（如需要）

根据排查需要，可能需要查询以下配置：

**查询配置快照**：
```
sre_query(action="config_snap", project_order_id="P001")
```

**查询字段配置**：
```
sre_query(action="field_config", business_type=1, gb_code=100, company_code="C001", contract_type=1, version=1)
```

**查询协议配置**：
```
sre_query(action="protocol_config", form_id=1)
```

### 第六步：解密敏感信息（如需要）

如果查询结果中包含加密的敏感信息（身份证号、手机号），使用解密接口：

```
sre_query(action="decrypt", encrypted_text="加密的密文")
```

**注意**：敏感信息仅用于排查目的，请勿泄露。

### 第七步：综合分析

基于收集到的数据，综合分析问题：

1. **问题描述**：用户反馈的问题是什么
2. **排查过程**：查询了哪些数据，发现了什么
3. **根因分析**：问题的根本原因是什么
4. **解决建议**：如何解决这个问题

## 输出格式

```markdown
## 排查结论

### 问题描述
[用户反馈的问题]

### 排查过程
1. 查询合同基本信息：[结果摘要]
2. 查询合同节点：[结果摘要]
3. 查询操作日志：[结果摘要]
4. 查询配置信息：[结果摘要]（如有）

### 根因分析
[问题的根本原因]

### 解决建议
[如何解决这个问题]
```

## 注意事项

1. **参数验证**：查询前确保有有效的 contract_code 或 project_order_id
2. **空结果处理**：如果查询返回空结果，可能是参数错误，检查后重试
3. **日志顺序**：操作日志按时间倒序排列，关注最近的记录
4. **数据安全**：敏感信息需解密后才能查看，注意保护用户隐私
5. **超时处理**：如果查询超时，稍后重试或联系技术支持

## 常见问题排查思路

### 合同签约失败
1. 查询合同状态，确认是否已签约
2. 查询合同节点，看卡在哪个环节
3. 查询操作日志，找最近的错误操作
4. 查询配置快照，确认配置是否正确

### 合同状态异常
1. 查询合同基本信息，确认当前状态
2. 查询合同节点，看流程是否异常
3. 查询操作日志，找状态变更记录

### 配置问题
1. 查询配置快照，确认配置内容
2. 查询字段配置，确认字段定义
3. 查询协议配置，确认协议模板
